# 原生模型菜单兼容方案

插件将多套适配规则一起发布，启动时识别本机 Devin 并检查实际程序文件。保留原生模型菜单和现有 Agent 执行流程。

本轮覆盖截至 2026-10-31 官方历史页列出的 3.10、3.11 系列 23 个 Windows x64 构建：

官方来源：[普通版历史页](https://docs.devin.ai/desktop/changelog)、[Next 历史页](https://docs.devin.ai/desktop/changelog-next)。精确提交、通道与规则映射记录在 `native-picker-releases.json`。这里按离散构建逐一列出，不代表整个版本号区间都已测试，也没有把 3.9 或更早系列标记为本轮验证版本。

每个方案覆盖 Sessions 和 Editor 两处菜单，各检查 10 个目标代码片段，包括选模状态、会话同步、发送预检和 SSH 模型入口。不同构建可共享完全一致的规则；同一官方提交出现在普通版和 Next 时，仍结合通道和构建号区分。3.10 旧菜单的价格变化标记、后续菜单的供应商信息都会保留。选模回调依赖包含当前模型目录，避免菜单加载后仍引用旧目录。

验证使用真实程序文件执行组件测试和隔离安装测试，不代表 23 个软件版本均在真实桌面窗口里完成全部功能的端到端测试。最终结果和逐版日志随发布包的 `matrix-results.json` 提供。

匹配顺序：

1. 根据官方提交号、构建号和通道确定候选方案。
2. 检查实际组件及所有目标代码片段，每个必须唯一匹配。
3. 未知构建可复用完全匹配的已有方案，日志标记为 `structure-reuse`，不将它标记成已验证版本。
4. 拒绝按最接近版本猜测、通道信息冲突、模糊匹配、重复片段和不同版本文件混装。已知版本信息与代码冲突时也拒绝写入。
5. 两处菜单全部检查通过后才统一写入、更新校验和；写入失败则回滚，卸载恢复原始内容。

在插件日志中搜索 `[NATIVE-PICKER] compatibility=` 可查看使用的方案、匹配方式、参考版本及已检查片段数量。失败时“查看兼容性诊断”提供版本和文件指纹，不输出聊天内容或登录令牌。

维护入口：`native-picker-releases.json` 登记构建，`native-picker-release-profiles.json` 保存经过验证的标识和代码片段，`native-picker-compat.cjs` 负责识别和交叉检查，`native-picker-next-311.cjs` 组装转换规则。运行时只读取随插件分发的本地规则。新方案必须经过真实文件测试后再标记为验证构建。测试入口为 `npm run test:native-compatibility`；逐版测试由 `scripts/test-native-picker-release-matrix.cjs` 执行对应组件、发送预检、SSH 入口及隔离安装/回滚测试。

完全改变组件或协议的未来版本仍需补适配。复用完整匹配的代码片段可以减少更新次数，不能保证未来版本永久兼容。
